### Draft issue

**Title:** Strip surrounding whitespace before making a slug

**Problem**

`slug()` turns every space into a hyphen, including spaces at the start or end of the input. As a result, padded input gives a slug with extra hyphens at the ends. For example, `slug(" Hello World ")` returns `"-hello-world-"`, and `slug("   ")` returns `"---"`.

**Intended result**

`slug()` must remove whitespace from the start and end of the input before it replaces the inner spaces with hyphens. It must still make the output lowercase, as it does now.

**Included changes**

- Change `slug()` in `slug.py` so that it removes surrounding whitespace before it replaces spaces.
- Add tests to `test_slug.py` for the new behavior.

**Out of scope**

- Changing how inner whitespace is handled, such as several spaces in a row or tabs between words.
- Removing punctuation, handling Unicode, or any other new slug rules.

**Success conditions**

| Input | Expected output | What it shows |
|---|---|---|
| `" Hello World "` | `"hello-world"` | New behavior: no hyphens from the padding |
| `"   "` (only whitespace) | `""` | New behavior: the result is an empty string |
| `"hello world"` | `"hello-world"` | Existing behavior is kept |
| `"Hello World"` | `"hello-world"` | Existing test `test_words` still passes |

To check: run `python3 -m unittest` and make sure all tests pass. Then read the new assertions and confirm they match the table.

**Tests to add**

- A padded-input test (`" Hello World "`). It shows that the end hyphens are gone.
- A whitespace-only test (`"   "`). It shows that the result is empty, not a string of hyphens.
- A test for unpadded lowercase input (`"hello world"`). It protects existing behavior.

The existing `test_words` already covers the lowercase rule.

**Confirmed decisions (from the original idea)**

- Remove whitespace from the start and end before replacing inner spaces.
- Keep the existing lowercase behavior.
- Input that is only whitespace becomes an empty string.

**Open questions (not blocking)**

1. **Tabs and newlines at the ends.** The idea says "whitespace," so I propose removing all surrounding whitespace, not only spaces. With this choice, `"\tHi\n"` gives `"hi"`. The tradeoff is that this is slightly broader than "spaces" in the problem statement.
2. **Several spaces in a row between words.** `"a  b"` gives `"a--b"` now. I propose keeping that unchanged and filing a separate issue if it matters.
